## Context

首页已具备文本和图片投递能力，但正式页面仍保留较多说明性结构；`/demo` 已验证更小的发送/取件双路径。详见 proposal.md。

## Goals / Non-Goals

**Goals:**
- 将 Demo 的层级与六码输入体验落到正式首页。
- 保持现有 API、错误语义、图片直传和会话存储行为。

**Non-Goals:**
- 不支持同一投递同时包含图文。
- 不改变创建、取件、删除接口或投递有效期。

## Decisions

### 发送与取件作为对偶路径

发送使用实心蓝按钮，取件使用蓝边按钮；两者由简短的 `or` 分隔。这样保留一个清晰的默认动作，同时让接收者立刻找到取件入口。

### 六码采用受控分格输入

首页管理六码单字符状态，支持输入、退格和粘贴，提交时合成为现有取件码。保留现有 API 调用和错误提示。

### 以 Demo 取代额外页面

将共享组件/样式迁移到正式首页，删除 Demo 路由和专用视图，避免两套首页长期分叉。

### 创建与取件页面以内容为中心

创建结果只保留二维码、六码、倒计时和删除动作；不展示长链接。文本取件页突出文本与复制动作，图片取件页突出图片与保存动作。所有结果页使用首页的蓝白、等宽标题和无卡片布局。

## Risks / Trade-offs

- [分格输入增加键盘边界情况] → 为输入、粘贴与退格添加前端测试和手工键盘验证。
- [极简页弱化敏感信息提醒] → 在创建前或结果页保留现有安全边界提示，不占据首页视觉主位。
