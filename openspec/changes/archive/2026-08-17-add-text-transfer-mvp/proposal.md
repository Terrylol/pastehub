## 背景

PasteHub 目前只有静态首页和健康检查接口，访客还无法完成其核心承诺：在一台设备放入短文本，在另一台设备无需登录即可取走。现在需要交付首个可用的完整闭环，以验证匿名临时文本传递是否足够快、适合普通用户。

## 变更内容

- 新增匿名文本投递创建能力：服务端生成不可枚举的取件链接和六码取件码。
- 接收者可通过链接标识或取件码读取仍有效的文本投递。
- 创建者拥有一次性的删除能力；投递创建十分钟后自动失效。
- 前端把模拟的发送与取件交互替换为真实文本投递 API，并覆盖创建成功、取件和失效状态。
- 为正常创建/读取、过期、删除、非法输入和取件码冲突补充自动化测试。

## 能力范围

### 新增能力

- `text-transfer`：单条临时文本的匿名创建、读取、删除和过期。
- `text-transfer-web`：浏览器中的文本投递创建，以及通过链接或取件码取件的流程。

### 修改的能力

- 无。

## 影响范围

- 后端：Spring Boot 的投递领域、REST 控制器、持久化配置、定时清理和测试。
- 前端：Vue 首页，新增创建结果、取件和失效页面，以及类型化 API 客户端。
- 数据：开发数据库增加临时 `transfers` 表；生产 MySQL 使用相同结构。
- 本变更不引入账号体系、图片传递、实时空间、加密或对象存储集成。
