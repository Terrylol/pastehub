## 上下文

仓库已有 Vue 3/Vite 前端原型、包含状态接口的 Spring Boot 后端，以及本地 MySQL/Redis/SeaweedFS Compose 定义。动机请见 `proposal.md`，对外行为以两份增量规格为准。本次实现有意先于图片传递，因此暂不需要对象存储路径。

## 目标 / 非目标

**目标：**

- 在既有前后端分离架构中交付浏览器到浏览器的完整文本交接。
- 在读取时以过期时间为准，同时通过后台回收已持久化的过期记录。
- 让创建者的删除权限保持私密，并仅限于创建者的当前浏览器会话。
- 建立可测试的 API 与 UI 边界，供后续图片传递扩展。

**非目标：**

- 图片上传、实时空间、端到端加密、认证、生产级限流和对象存储。
- 不承诺链接或短码的机密性；当前版本没有加密。

## 设计决策

### 在关系型数据库中持久化投递元数据与文本

使用 `transfers` 表保存随机 UUID 标识、唯一六码、文本正文、创建/过期时间和删除令牌哈希。相较于仅使用 Redis，它更简单且更可靠，同时保持与既定 MySQL 方向兼容。H2 仍是零配置的开发与测试默认数据库。

备选方案：以 Redis TTL 为主存储。它简化自动过期，但会使持久化和本地测试偏离规划中的生产关系型数据库。

### 将过期处理设为读取时规则加定时清理

每次读取或解析取件码时，都在返回数据前检查 `expiresAt`；已过期记录立即删除并返回不可用。定时清理会移除未被读取触发清理的过期记录，即使清理任务延迟也能保证行为正确。

备选方案：只依赖周期任务。这会让内容在到期至下一次任务执行之间仍可能被返回。

### 使用不透明随机标识、防碰撞取件码与哈希删除令牌

标识使用随机 UUID。取件码从 32 个不易混淆字符中生成，以数据库唯一约束兜底并进行有限重试。服务端只返回一次随机删除令牌，仅持久化其 SHA-256 哈希，并以常量时间比较哈希。

备选方案：顺序标识和可逆删除令牌。它们会显著增加枚举和意外泄露的风险。

### 提供精简 REST 契约，并按标识路由单页应用

后端在 `/api/v1/transfers` 下提供文本创建、按标识读取、取件码解析和删除。Vue Router 提供 `/`、`/created/:id`、`/t/:id` 与 `/expired`；类型化前端服务统一处理 HTTP 调用。创建结果页将删除令牌写入 `sessionStorage`，绝不写入 URL；二维码在浏览器中由取件链接生成。

备选方案：带片段状态的单页面。它会导致分享链接、直接取件和浏览器刷新行为不可靠。

## 风险 / 取舍

- [链接或取件码可被转发] → 持续展示敏感内容提醒，且绝不宣称当前版本加密。
- [六码碰撞会随体量上升] → 强制唯一性并重试生成；在改变码长前观察碰撞重试情况。
- [删除前浏览器会话可能关闭] → 明确手动删除权限仅限当前会话；十分钟自动过期仍可用。
- [H2 与 MySQL 存在细微差异] → 保持 SQL 和实体可移植；当前用 H2 跑集成测试，上线前新增 MySQL CI 服务。

## 迁移计划

1. 通过同时适用于 H2 和 MySQL 的应用迁移新增 `transfers` 表结构。
2. 先部署后端，再部署前端，保证浏览器仅在 API 可用后访问新界面。
3. 回滚时恢复上一版前后端；临时投递记录可自然过期，再由正常清理路径移除。

## 开放问题

- `pickupUrl` 的生产域名可在部署时确定；这不会改变标识、API 行为或浏览器路由。
