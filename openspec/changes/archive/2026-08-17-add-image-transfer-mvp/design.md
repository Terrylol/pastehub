## 上下文

文本投递 MVP 已完成，前端有 Vue Router 和创建/取件页面，后端有临时投递、TTL 与删除能力。Compose 已预置 SeaweedFS S3 网关，但尚未被业务使用。本变更只扩展图片投递，不改变现有文本契约。

## 目标 / 非目标

**目标：**

- 以浏览器直传降低 Spring Boot 的图片带宽与内存压力。
- 在发布前对图片类型、体积和对象存在性进行双端校验。
- 让对象生命周期与投递的删除/过期状态一致。

**非目标：**

- 多文件、任意文件格式、图像压缩/转码、病毒扫描、端到端加密和 CDN 缓存。

## 设计决策

### 两阶段直传

`POST /image/init` 验证声明的类型和大小，创建五分钟有效的 pending 记录并签发仅允许对应对象键的预签名 PUT URL 与上传令牌；浏览器上传后调用 `/image/complete`。完成接口通过 S3 HEAD 再次验证对象大小和 MIME，再发布投递、分配六码与删除令牌。

备选方案是经 Spring Boot 代理上传。其实现较短，但会占用应用实例带宽和内存，且后续扩展成本更高。

### 受限对象键与短时读取 URL

对象键按 `transfers/{id}/image` 生成，永不直接暴露。已发布图片读取时由 API 签发约 60 秒的 GET URL；pending 对象和已过期对象永远不签发读取 URL。

### 同步可用性、异步物理清理

删除或过期先使数据库记录不可用，随后删除对象；若删除失败，定时任务按对象键重试。待上传记录五分钟后清理。数据库状态是读取时唯一可信来源。

## 风险 / 取舍

- [客户端伪造 MIME] → 初始化阶段限制，完成阶段 HEAD 校验，并在后续迭代引入魔数检测或对象扫描。
- [用户中断上传] → pending 五分钟自动回收，并不生成取件码。
- [预签名 URL 泄露] → URL 仅限单一对象、短时有效，且不等同于取件链接。
- [SeaweedFS 本地/生产配置差异] → 通过 S3 SDK 抽象，使用 Compose 做本地冒烟测试。

## 迁移计划

1. 迁移 `transfers` 表以区分文本、图片与 pending 状态。
2. 配置 SeaweedFS bucket 与受限开发凭据，再部署 API。
3. 部署前端；如需回滚，停止签发图片 URL，现有图片对象由清理任务回收。
