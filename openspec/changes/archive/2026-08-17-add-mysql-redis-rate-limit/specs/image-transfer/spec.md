## MODIFIED Requirements

### Requirement: 创建图片投递
系统 SHALL 仅接受 JPEG、PNG 或 WebP 图片，且单个图片不得超过 10 MB。系统 MUST 在图片被成功上传并经服务端确认前不分配取件码或公开取件链接。发布后的图片投递 MUST 在创建后十分钟失效。超过客户端 IP 的图片初始化或发布限流时，系统 MUST 返回限流响应且不得公开投递。

#### Scenario: 发布有效图片
- **WHEN** 访客提交一张符合类型和大小限制的图片并完成上传
- **THEN** 系统发布图片投递，并返回标识、六码、取件链接、过期时间与删除令牌

#### Scenario: 拒绝不支持的图片
- **WHEN** 访客提交非 JPEG、PNG、WebP 格式或超过 10 MB 的图片
- **THEN** 系统拒绝该投递且不公开取件方式

#### Scenario: 图片初始化被限流
- **WHEN** 访客所在客户端 IP 在限流窗口内已超过图片初始化配额
- **THEN** 系统返回限流响应且不创建 pending 图片投递

#### Scenario: 图片发布被限流
- **WHEN** 访客所在客户端 IP 在限流窗口内已超过图片发布配额
- **THEN** 系统返回限流响应且 pending 图片不获得取件码或公开链接

### Requirement: 清理图片对象
系统 SHALL 在创建者删除、投递过期或上传在五分钟内未完成时，使关联对象不可访问并安排删除。删除操作 MUST 保持幂等，且不得影响其他投递对象。超过客户端 IP 的删除限流时，系统 MUST 不改变图片投递或关联对象状态。

#### Scenario: 删除已发布图片
- **WHEN** 创建者使用有效删除令牌删除一条图片投递
- **THEN** 该图片立即不可取件，关联对象被清理或进入可靠的清理队列

#### Scenario: 图片删除被限流
- **WHEN** 创建者所在客户端 IP 超过删除接口配额
- **THEN** 系统返回限流响应且图片仍可按其原有有效状态取件
