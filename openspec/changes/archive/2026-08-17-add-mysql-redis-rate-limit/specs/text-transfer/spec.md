## MODIFIED Requirements

### Requirement: 创建临时文本投递
系统 SHALL 接受非空且不超过 10,000 个字符的文本，并创建一条在创建后恰好十分钟过期的临时投递。创建响应 MUST 包含不可枚举的投递标识、使用无歧义字符的六码大写取件码、取件 URL、过期时间戳和仅创建者可用的删除令牌。响应及删除令牌 MUST NOT 被缓存。超过客户端 IP 的创建限流时，系统 MUST 返回限流响应且不得创建投递。

#### Scenario: 创建有效文本
- **WHEN** 访客提交非空且未超过最大长度的文本
- **THEN** 系统返回投递详情，并在过期时间前提供该文本

#### Scenario: 拒绝无效文本
- **WHEN** 访客提交空文本或超过 10,000 个字符的文本
- **THEN** 系统拒绝请求且不创建投递

#### Scenario: 文本创建被限流
- **WHEN** 访客所在客户端 IP 在限流窗口内已超过文本创建配额
- **THEN** 系统返回限流响应且不创建投递

### Requirement: 投递过期和删除
无论后台清理是否已经执行，系统 SHALL 在投递达到过期时间后使其不可用。创建者 SHALL 能通过删除令牌删除投递。已删除、已过期和未知的投递在读取或解析取件码时 MUST 返回同一种不泄露信息的不可用响应。对于有效的创建者删除令牌，删除 MUST 是幂等的。超过客户端 IP 的删除限流时，系统 MUST 不改变投递状态。

#### Scenario: 无法读取已过期投递
- **WHEN** 接收者在投递过期后请求它
- **THEN** 系统返回不可用响应且不返回文本

#### Scenario: 创建者删除投递
- **WHEN** 创建者为有效投递提供删除令牌
- **THEN** 系统立即使其不可用，且重复删除请求成功但不泄露内容

#### Scenario: 拒绝无效删除权限
- **WHEN** 调用方没有创建者删除令牌却尝试删除投递
- **THEN** 系统拒绝删除，并保持有效投递可用

#### Scenario: 文本删除被限流
- **WHEN** 创建者所在客户端 IP 超过删除接口配额
- **THEN** 系统返回限流响应且目标投递保持原状态
