## Purpose

为匿名写入接口提供跨应用实例一致的 IP 访问频率控制，在不要求用户登录的前提下保护临时投递服务免受批量滥用。

## Requirements

### Requirement: 限制匿名写入请求
系统 SHALL 对文本创建、图片初始化、图片发布和投递删除接口按客户端 IP 实施可配置的限流。系统 MUST 在超出限制时返回 `429 Too Many Requests`，并且不得创建、发布或删除投递。

#### Scenario: 同一 IP 超出创建限制
- **WHEN** 同一客户端 IP 在配置窗口内提交的文本创建请求超过限制
- **THEN** 系统返回 429，且被拒绝的请求不创建投递

#### Scenario: 不同 IP 独立计数
- **WHEN** 两个不同客户端 IP 分别提交未超过其各自限额的创建请求
- **THEN** 系统分别允许这些请求，不共享访问计数

### Requirement: 提供可预期的限流反馈
系统 SHALL 在限流响应中提供机器可识别的错误码和重试等待信息。限流阈值和时间窗口 MUST 可由运行环境配置，且限流状态 MUST 在应用实例之间共享。

#### Scenario: 客户端收到限流响应
- **WHEN** 请求被限流
- **THEN** 响应包含一致的限流错误码和 `Retry-After` 信息
